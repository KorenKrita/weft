# AGENTS.md

Guidance for coding agents working in this repository.

Weft is a local-first macOS (26+) menu bar time tracker written in Swift 6 / SwiftUI / SwiftData. It classifies activity with rules plus Apple's on-device Foundation Models; nothing leaves the Mac.

## Commands

`Weft.xcodeproj` is generated by XcodeGen from `project.yml` and git-ignored. Regenerate it after adding, removing or renaming files under `App/`, or after editing `project.yml`.

```sh
xcodegen generate
xcodebuild -project Weft.xcodeproj -scheme Weft -derivedDataPath build/DerivedData build
open build/DerivedData/Build/Products/Debug/Weft.app
```

Tests live only in the `WeftKit` package and use Swift Testing (`@Test`, `#expect`), not XCTest:

```sh
cd Packages/WeftKit
swift test                                                   # all unit tests
swift test --filter SessionEngineTests                       # one suite
swift test --filter "SessionEngineTests/startAndExtend"      # one test
WEFT_AI_TESTS=1 swift test --filter FoundationModelsHarness  # real on-device model (needs Apple Intelligence)
```

Signing: `Config/Base.xcconfig` signs ad hoc by default, and optionally includes the git-ignored `Config/Local.xcconfig` (copy it from `Local.xcconfig.example`). With ad hoc signing, macOS drops the Accessibility grant after every rebuild, so window titles stop showing up until you grant it again.

The app icon (`App/AppIcon.icon`, Icon Composer format) is generated by `python3 scripts/make-glass-icon.py`. Don't edit the SVGs by hand.

## Architecture

There are two layers:

- **`Packages/WeftKit`**: all logic (tracking, storage, classification, metrics, sessions), with no UI. Put anything you want to unit test here.
- **`App/`**: the SwiftUI shell. `LSUIElement` app with a menu bar popover (`MenuBar/`), a main window (`Main/`) and full-screen break/blocker overlays (`Overlays/`). It also handles the `weft://` URL scheme (in `WeftApp.swift`).

`App/Support/AppModel.swift` is the composition root. It creates the single SwiftData `ModelContainer` and every long-lived service, and connects them in `wire()`. Services don't know about each other directly; they talk through closures (`onStart`, `onEnd`, `requestRecheck`, `onIncidentChange`, `notifier.onAction`) and through tracker listeners. All services are `@MainActor @Observable` and share `container.mainContext`.

### Data flow

1. **Tracking** (`Tracking/`): `ActivityTracker` is event-driven to save power. `WindowEventObserver` (AX/workspace notifications) triggers a sample when the app, window or title changes. On top of that there's a 60 s heartbeat, a one-shot idle timer and a slower check while the user is away. There is no fast polling loop; keep it that way. `TitleChangeThrottle` mutes noisy title changes, such as terminal spinners. `BrowserURLProvider` reads the tab URL via Apple Events. Each sample builds an `ActivityContext`. `TrackingStateMachine` is pure (no AppKit or storage, unit tested) and turns samples into `.open/.extend/.close` effects, which the tracker applies to `ActivitySegment` records. Idle (5 min), sleep, lock and pause close the segment. Meetings are exempt from the idle cut. Every sample also goes out as a `TrackerSample` to listeners (break reminder, work hours, distraction guard).
2. **Classification** (`Classification/`): `ClassificationService.classify` tries, in order:
   1. `RuleEngine` (user rules + about 360 `BuiltinRules`)
   2. the cached AI answer, keyed by `ActivityContext.classificationKey` (bundle ID, plus the domain for browsers)
   3. a background queue to `AIClassifying` (`FoundationModelsClassifier`)

   While a segment waits on the model, it is stored as `uncategorized` with source `.pending`, and gets patched in place when the answer arrives. Adding or deleting a rule reclassifies matching past segments, except `.manual` ones. At launch, `Maintenance.run` lets newer rules override old AI answers.
3. **Metrics** (`Metrics/`): pure functions over segments. `ActivityBlocks` builds the activity log rows and folds short detours into them. `TimeEntries` builds the overlapping per-category "work streams" on the Today timeline: same category within 30 min forms one stream, and only streams of 10 min or more count as significant. `DayMetrics` computes the Focus Score.
4. **Descriptions**: `TimeEntryService` queues finished streams for a one-sentence on-device description, cached in `TimeEntrySummary` by `TimeEntry.key` (category + start). `AppModel` runs it every ~5 min.
5. **Sessions** (`Sessions/`): `SessionEngine` handles Focus, Meeting and Break sessions. `DistractionGuard` triggers the blocker overlay when the user stays in a category marked `blockInFocus` during a focus session. `Reminders` holds the break and work-hours monitors, and `Notifier` wraps `UNUserNotificationCenter`.

### Storage

SwiftData models live in `Storage/Models.swift`, and the schema list is `WeftSchema.models`; add every new `@Model` there. The store is at `~/Library/Application Support/Weft/Weft.store`. Enums are stored as raw strings (for example `classificationSourceRaw`) so that `#Predicate` can filter on them. Keep that pattern when adding filterable enum fields. Categories are seeded from `CategoryDefinition.defaults` and referenced everywhere by string `key`.

### Testing patterns

Tests use `WeftSchema.makeContainer(inMemory: true)` and a stub `AIClassifying` (for example `NoAI` in `SessionEngineTests`) so they never call the real model. Code that depends on AppKit or Accessibility goes behind pure types, like `TrackingStateMachine` and `TitleChangeThrottle`, which are what the tests cover.
